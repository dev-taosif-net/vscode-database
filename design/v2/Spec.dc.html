Build sheet
Every neutral surface reads a VS Code theme token, so the page follows the user's theme, high contrast ones included, with no theme code of its own. Colour is added on top of that, and only where it carries meaning: which engine, which environment, how safe the transport is, and how the last attempt ended.
Colour systems
Engine identity

Environment
A bar, a dot or a pill, plus a wash behind the header at ten per cent. Never a solid fill.
TLS strict SSL prefer
Transport strength
A chip in the header. Teal verified, amber weakened, red off. It changes the moment a setting weakens the connection.
Result
The strip above the action bar, with a 3px left edge. Reuses the theme's own testing colours.
Product accent
The primary button, the focus ring and the active section bar. Taken from the theme, never chosen here.
Each system owns a shape, so two of them never compete for the same pixel. Colour is never the only carrier of meaning either: the environment pill spells out PROD, the transport chip spells out its mode, and every result strip has an icon and a sentence. Around one in twelve men and one in two hundred women have some colour vision deficiency, and the page has to work for all of them in grayscale.
Environment behaviour
DEV #3FB84F light #1A7F37
No guards. Metadata is cached for the whole session so the object tree opens instantly.
QA #4A93F0 light #0B62CE
An UPDATE or DELETE with no WHERE clause asks for confirmation before it runs.
UAT #E08A3C light #B45309
The same guard as QA, and the environment name goes into the query history.
PROD #F0563F light #C6362A
Read-only sessions, a confirmation before connecting, no stored credential by default, and schema changes refused until the session is switched to read-write.

Credential rules
1Secrets live in the VS Code secret store, which is the operating system keychain. Nothing secret is written to settings.json or to any file in the workspace.
2Settings Sync carries connection shapes between machines, never credentials.
3The connection string preview and every log line the extension writes mask the secret.
4Production connections default to asking for the credential on every connect.
5Deleting a connection deletes its secret in the same step, with no orphan left behind.
