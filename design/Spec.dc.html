Build sheet
Nothing on this page invents a colour, a size or a font. Every surface reads a VS Code theme token, so the page follows the user's theme, including the high contrast ones, with no theme code of its own. The four environment colours are the only literals, and they are always paired with a text label.
Environment system
Development #3FB84F light #1A7F37
No guards. Metadata is cached for the whole session so the object tree opens instantly.
QA #4A93F0 light #0B62CE
An UPDATE or DELETE with no WHERE clause asks for confirmation before it runs.
UAT #E08A3C light #B45309
Same guards as QA, and the environment name is written into the query history.
Production #F0563F light #C6362A
Read-only sessions, a confirmation before connecting, no stored credential by default, and schema changes refused until the session is switched.
Colour appears in four places only: a 2px bar on each list row, a 3px bar beside the connection name, the environment pill, and the production confirmation. It never fills a surface and never carries meaning on its own, because roughly one man in twelve cannot separate the green from the red.

Credential rules
1Secrets live in the VS Code secret store, which is the OS keychain. Nothing secret reaches settings.json, the workspace file or the team file.
2Settings Sync carries connection shapes between machines, never credentials.
3The connection string preview and every log line the extension writes mask the secret.
4Production connections default to asking for the credential on every connect, so an unattended laptop cannot open a live session on its own.
5Deleting a connection deletes its secret in the same step, with no orphan left in the keychain.
